## 2. What was measured

1. **Call-site probe** (`cargo run -p rustlab-cli --release --example add_probe`),

   `docs/verify-logs/2026-10-28-g0.1-verify-add-probe-original-run1.txt`,
   `...-run2.txt`, and `...-run3.txt`.
2. **Criterion harness** (`cargo bench -p rustlab-stdlib --bench a312 -- "a312/elementwise_add"`).
   Raw output for the unmodified code:

   The two experimental refactor attempts are also retained:
   `...-add-criterion-inline.txt` and `...-add-criterion-split.txt`.

## 3. Results (unmodified production code)

Three fresh release runs of the call-site probe:

| Run | `Value::add` median | manual zip loop median | interpreter median |
| :--- | ---: | ---: | ---: |
| 1 | 0.491 ms | 0.506 ms | 0.498 ms |
| 2 | 0.656 ms | 0.628 ms | 0.579 ms |
| 3 | 0.513 ms | 0.585 ms | 0.533 ms |
| **Median of runs** | **0.513 ms** | **0.585 ms** | **0.533 ms** |

The public `Value::add` is therefore **not slow** when called from a normal
inlined call site: it is within measurement noise of a manual same-shape loop
and of the interpreter pipeline.

The criterion `raw_Value_add` benchmark measured **6.0169 ms** on the
unmodified code, while its interpreter benchmark measured **1.0834 ms**.
That gap is a harness/inlining effect: criterion's `Bencher::iter` closure
does not inline the public call, so the raw benchmark exercises the
non-inlined scalar path. The call-site probe is the measurement that matches
how the binary `+` and interpreter fast path use the function.

## 4. Experimental refactors and why they were reverted

Two production refactors were tried and measured:

1. `#[inline]` on the existing `Value::add`: criterion raw **7.6599 ms**,
   interpreter **1.2326 ms**.
2. A small inline wrapper plus an out-of-line mixed-type dispatch: criterion
   raw **7.5576 ms**, interpreter **1.1649 ms**.

Neither improved the call-site probe, and both made the non-inlined criterion
path slower than the original 6.0169 ms. Both edits were reverted. At the end
of this note, `git diff -- crates/rustlab-math/src/value.rs` is empty; the
milestone contains no production add-path change.

## 5. What this note does not claim

- No claim is made that REA inspected the binary in this session.
- No instruction addresses or disassembly are presented here.
- The criterion raw-path number is retained as a harness artifact; it is not
  used as evidence that the public API is slow in normal call sites.
- The probe is a Rust-level measurement, not a MATLAB-level comparison.
