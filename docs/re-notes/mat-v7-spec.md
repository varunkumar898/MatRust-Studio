# MAT-File Level 5 / Version 7 Specification Notes & SciPy Interop Validation

**Analyst role**: this document is an ANALYST-side functional specification of the
MAT-file Level 5 (Version 7) binary layout as exercised by `scipy.io.savemat` /
`scipy.io.loadmat` (SciPy 1.18.1, Python 3.14 ARM64), plus the interop test results
against `rustlab-matio`.

Reference: scipy.io.savemat docs (MAT Level 5 format: `_mat_struct.md` MAT spec,
"MATLAB MAT-file V7" = Level 5 + `miCOMPRESSED` blocks).

---

## 1. On-disk model exercised by the fixture suite

```
128-byte header:  text[116], subsystem_offset[8], version u16 (0x0100), endian "IM"
--- top-level element stream (each: tag = type u32 + num_bytes u32) ---
  miMATRIX payload:
     1) miUINT32 array flags  (class_id byte, flags byte, reserved[6])
     2) dims (miINT32, n_dims x 4 bytes, then 8-byte alignment)
     3) array name (miINT8)
     4) class-specific body
```

Class-specific bodies (`mxCLASS_*`), verified from the SciPy fixtures:

| class | body after name |
| :--- | :--- |
| `mxDOUBLE_CLASS` / `mxSINGLE` / int classes | real data (`miDOUBLE`/`miSINGLE`/`miINTxx`/...), then `miDOUBLE` imaginary part iff `FLAG_COMPLEX` |
| `mxUINT8` + `FLAG_LOGICAL` | `miUINT8` booleans (0/1) |
| `mxCHAR` | `miUINT16` UTF-16 code units (SciPy default), one per char |
| `mxCELL_CLASS` | `total_elements` consecutive nested `miMATRIX` elements |
| `mxSTRUCT_CLASS` | Field-name length (`miINT32`, N bytes/name, SciPy=32) -> packed field names (`miINT8`, `num_fields*N`, NUL-padded) -> per element `num_fields` nested `miMATRIX` in field order |
| `mxSPARSE_CLASS` | `ir` (miINT32 row indices), `jc` (miINT32 column pointer), `pr` (`miDOUBLE` values) |

### Padding rule (found via binary probing, CALL-LOG 08:02:38)

- Uncompressed elements: aligned to **8-byte boundaries** (padding inserted).
- `miCOMPRESSED` top-level blocks: **no padding between consecutive blocks**
  (this made `rustlab-matio` mis-read suite files until the compressed stream
  reader skipped padding only for non-compressed elements).

## 4. Implementer action triggered by this table (clean-room handoff)

**Finding (ANALYST)**: `var_struct` decoded as a junk `double [1,1]`.

**Root cause**: `crates/rustlab-matio/src/reader.rs::decode_matrix` had no
`mxSTRUCT_CLASS` branch, so the struct fell through into the numeric real-data
reader, which parsed the field-name buffer as f64s.

**Requirement written for the IMPLEMENTER** (delivered, verified):

After the array name, for `class_id == 2` read

1. field-name length element (`miINT32`) -> `N` (SciPy uses 32),
2. packed field names (`num_fields * N` bytes, each NUL-padded),
3. `total_elements * num_fields` consecutive nested `miMATRIX` elements in
   field-name order, grouped per array element.

**Post-fix verification probe** (CLI, `load(...).var_struct`):

```
  struct with fields:

    field_name: 'RustLabEngine'
    field_id:     42
    field_matrix:        1     0
       0     1
```

Interop table now reads 40/40 PASS.
