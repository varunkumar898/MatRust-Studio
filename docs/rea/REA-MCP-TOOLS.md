# REA MCP Tools Inventory and Schema Reference

This catalog documents the tools exposed by the Reverse Engineering Analysis (REA) MCP server running in Antigravity (`node C:\Users\varun\.antigravity\rea\scripts\rea.mjs mcp`), as verified during the MatRust Studio desktop GUI research phase.

## Total Discovered Tools: 116

### 1. Static Binary Inspection & PE Analysis
- `open_binary`: Opens an executable file for reverse engineering analysis.
  - Input schema: `{ target: string }`
  - Output: Session handle, binary format, architecture, and file SHA-256 hash.
- `binary_session`: Returns active binary session metadata.
- `close_binary`: Closes an active binary session.
  - Input schema: `{ session?: string }`
- `inspect_binary_layout`: Returns section headers, virtual addresses, sizes, and permissions (.text, .rdata, .data, .pdata).
- `inspect_analysis_view`: Provides structural analysis metrics, functions identified, string counts.
- `inspect_pe_imports`: Dissects PE Import Table (DLL dependencies and imported functions).
  - Input schema: `{}` (uses active binary session)
  - Crucial for identifying frameworks (CEF, protobuf, Win32 APIs, graphics backends).
- `inspect_pe_exports`: Dissects PE Export Address Table (EAT) functions and ordinals.
- `inspect_pe_certificates`: Verifies Authenticode signatures, certificates, and signer identity.
- `inspect_pe_resources`: Inspects PE resources (manifest, dialogs, icons, string tables).
- `list_segments`: Lists virtual memory segments and sections.
- `list_strings`: Extracts ASCII/UTF-16 string literals from the binary.
- `search_strings`: Searches string constants for keywords (e.g., "cef", "v8", "qt", "dock").

### 2. Disassembly and Decompilation
- `read_function_instructions`: Disassembles machine instructions for a procedure.
- `procedure_pseudo_code`: Generates decompiled pseudo-C code for a target procedure.
- `batch_decompile` / `decompile_all`: Decompiles batches of discovered functions.
- `analyze_function`: Comprehensive analysis of control flow, loops, and local variable frames.
- `get_call_graph`: Generates call hierarchy for procedures.
- `xrefs` / `find_xrefs_to_name`: Identifies cross-references to symbols and memory addresses.

### 3. Native UI Observation and Scenario Capture
- `inspect_desktop_application`: Inspects top-level windows and process trees of desktop applications.
  - Input schema: `{ process_id?: number, executable_name?: string }`
- `observe_native_ui`: Inspects UI hierarchy and control elements.
  - Note on Win32/CEF: Pure Win32 window handles return accessibility trees; Chromium Embedded Framework (CEF) windows host web content internally.
- `capture_native_ui_scenario`: Records sequences of UI interactions and window states.
- `trace_native_ui_action`: Traces events generated by UI clicks, keyboard focus, and window events.
- `observe_native_calls`: Hooks and observes native runtime API calls.

### 4. Dynamic Instrumentation & Debugging
- `start_rizin_debug_session` / `rizin_debug_command` / `close_rizin_debug_session`: Native debugger control via Rizin.
- `start_gdb_session` / `gdb_console` / `close_gdb_session`: GDB engine control.
- `list_frida_processes` / `start_frida_session` / `instrument_with_frida`: Dynamic runtime instrumentation via Frida.

### 5. Evidence Bundles & Reconstruction Verification
- `export_evidence_bundle` / `import_evidence_bundle`: Bundles verified findings into structured JSON artifacts.
- `verify_reconstruction`: Compares target executable characteristics with independently implemented artifacts to verify architectural fidelity without code infringement.
- `compare_bundles`: Performs semantic diffs between reverse-engineering evidence bundles.
